## E12-conditional-validation — Conditional / cross-field validation
Goal: Make one field required only in a specific branch: the free-text "details" input is mandatory when the reason is `other`, and irrelevant otherwise — with no conditional rules, by choosing which declared fields to check.
Mechanisms:
- **Unconditional rules** — both `type` and `details` are declared `required: true` on the `Form` (`id: "reason"`, `valueKey: "form"`).
- **`scope` decides what is checked** — Submit runs an `if`: for `other` it calls `form.validate` with `scope: ["type", "details"]`, otherwise `scope: ["type"]`. Rules apply to declared fields whether or not their input is mounted, so the `if` on the details input alone would not switch its rule off.
- **Branch-gated input** — the `details` `TextInput` carries `if: "vm.form.type = 'other'"`, so it is only on screen when it applies.
- **Clear stale values** — the reason `Select`'s `onChange` clears `vm.form.details` whenever the choice is not `other`.
- **`if` client action** gates the submit on `vm.valid.form` after validating.

## E11-wizard — Multi-step wizard form
Goal: Walk a user through a form in three steps using a single view-model counter (`vm.step`) and one shared `Form` — only the active step is on screen and checked on Next, Back/Next never lose entered data, and Submit checks everything.
Mechanisms:
- **`if` per step section** — each step is a `Stack` gated by `if: "vm.step = N"`. A falsy `if` unmounts the node _and its subtree_, so the other steps' inputs do not exist while you are on the current one. Their **values** survive, because they live in the view model, not in the inputs.
- **One shared `Form`** (`valueKey: "wizard"`) wraps all three step sections. Every field's value lives at `vm.wizard.<name>`; child inputs are two-way bound (value binding + a `state` action on change).
- **Rules belong to declared fields, not to inputs** — `form.validate` without `scope` checks every declared field, mounted or not. So Next scopes the check to the step on screen: `scope: ["firstName", "lastName"]` on step 1, `["email", "company"]` on step 2, and advances only when `vm.valid.wizard = true`.
- **Submit checks the whole form** (no `scope`). Valid → `form.submit` via `corezoid`; invalid → jump to the first step with an error and warn.
- **`form.submit` does not validate itself**, and a non-2xx reply still runs `onSuccess` — so the success toast checks `$event.code`.

## E22-data-grid — Server-driven data grid (filter + sort + paginate)
Goal: Render a read-only tabular grid whose filtering, sorting and pagination are all performed by the backend. The client keeps only the current page of rows plus a small `query` descriptor; every toolbar interaction round-trips to `customer/list` and replaces `vm.rows` and `vm.total`.
Mechanisms:
- **`Table` primitive** for the tabular data — read-only, declarative `columns` + `dataSource`. Because there are no clickable rows, per-row buttons or badges-in-cells here, `Table` is the right tool (see the Pitfalls for when it is not).
- **`state` (merge)** to patch a single field of `vm.query` without rebuilding the whole object.
- **`simapi.call` with `assignTo: "page"`** to fetch the new page. `assignTo` names the reply `$result.page` for the rest of the chain only; two `state.set` actions then copy `$result.page.rows` and `$result.page.total` into `vm.rows` / `vm.total`.
- **`Pagination` emits the page as a plain number** (`$event`), while the search field and the select emit `{ value }` (`$event.value`).
- **`{{ vm.query }}` as a whole-string param** so the raw object (not a stringified copy) is sent as the JSON-RPC params.

## E10-workspace — Composed workspace: tabs + loops + conditionals
Goal: A capstone that composes the earlier foundations into one screen: a `Tabs` strip over three panels — Overview (aggregate stat cards), Accounts (the E03-style for-list), and Settings (a toggle + a conditional hint). Fully view-model-driven, renders with no backend.
Mechanisms:
- A controlled `Tabs` strip: `value` is `{{ vm.tab }}` and `onChange` writes the clicked tab's value (`$event`, a string) back to `vm.tab`. Each `TabItem` is a leaf — it renders only its tab, never a panel.
- Three panels as siblings below the strip, each gated by `if: "vm.tab = '…'"`.
- Aggregate expressions `$sum(vm.accounts.balance)` and `$count(vm.accounts)` in stat cards (Expressions §sealed/native funcs).
- `for` directive for the accounts list, with a `navigate.local` per row (as in E03).
- `state` `merge` action writing a partial patch into `vm.settings` (Client actions).
- A conditional-text `Label` reading the merged flag (`{{ … ? … : … }}`).
- `Row`/`Col` (`span`) layout for the stat grid.

## E03-loop-list — List via for-loop with per-row action
Goal: Render one Card per account from `vm.accounts` using a `for` directive, and give each row an "Open" button that navigates locally carrying that row's id.
Mechanisms:
- `for` directive — repeats a node's subtree once per array item (TreeNode §`for`): `items`, `as`, `keyBy`.
- A plain node id (`acc`) — the renderer derives each repeat's id from `keyBy` (`acc:1`, `acc:2`). Templated ids (`acc-{{ $acc.id }}`) are refused by sim-api when a page is saved.
- Loop-scoped `$acc` variable inside the subtree (Expressions §bound `$` variables).
- `navigate.local` client action with a `query` map whose values are `{{ }}` expressions (Client actions).

## R01-page-routing — Short URLs declared in a page config
Goal: Give a Smart Form page readable, shareable addresses — `/sf/{appKey}` and `/sf/{appKey}/sales/main` — next to its technical URL `/{workspaceId}/{scriptRef}/{environment}/index`, and hand the page the resolved entities through `$route` so a `GraphEditor` opens the right graph and layer.
Mechanisms:
- **`routes`** — an optional, additive top-level field of the page config. Each route has a Smart-Form-unique `name`, a `path` relative to `/sf/{appKey}`, and one `params` entry per `:param`. The page is the implicit target; no route is implicit (`"path": "/"` is declared).
- **Typed parameters** — `slug` (`[a-z0-9]+(-[a-z0-9]+)*`), `uuid` (canonical lowercase), `int` (a JSON number). A `slug` may name the form of the actor it addresses: `"actor": { "systemForm": "Graphs" }` or `{ "formId": 1234 }`.
- **Slug = `actors.ref`** — the runtime resolves each `actor` parameter with `actor/by-ref/get` and exposes the UUID as `$route.ids.<param>`; a missing or invisible actor is NotFound.
- **`$route`** — the authoritative route context from `page/render`: `{ kind: "direct", params: {} }` on the technical URL, `{ kind: "dynamic", appKey, name, params, canonicalPath, ids }` on a short one. Injected by the host, like `$query`.
- **Pathname vs fragment** — the pathname picks the page and `$route`; the block's own state stays in `#b=graph:<graphId>%3A<layerId>` and wins over the initial props.
pages/<page>/config:
{
  "schemaVersion": "2.0",
  "id": "index",
  "title": "Graph editor",
  "routes": [
    {
      "name": "graph.home",
      "path": "/"
    },
    {
      "name": "graph.layer",
      "path": "/:graph/:layer",
      "params": {
        "graph": {
          "type": "slug",
          "actor": {
            "systemForm": "Graphs"
          }
        },
        "layer": {
          "type": "slug",
          "actor": {
            "systemForm": "Layers"
          }
        }
      }
    }
  ],
  "tree": {
    "id": "root",
    "type": "Stack",
    "props": {
      "direction": "vertical"
    },
    "children": [
      {
        "id": "graph",
        "type": "GraphEditor",
        "props": {
          "actorId": "{{ $route.ids.graph }}",
          "layerId": "{{ $route.ids.layer }}"
        }
      }
    ]
  }
}
