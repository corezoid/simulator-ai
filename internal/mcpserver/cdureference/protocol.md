## page — the page config: the file pages/<page>/config
Normative JSON Schema for stored page configs (a Smart Form file pages/<pageId>/config, authored as JSON). sim-api validates every saved file whose JSON has schemaVersion and tree against it, then each node's props against cdu-catalog.schema.json.
A Smart Form is a set of pages; each page is a tree of nodes over its own data, wired by actions.
Smart Form
├─ config · viewModel · locale     app-wide: shared data and texts
├─ theme                           tokens, the themes a viewer may switch
├─ definitions/<name>              subtrees a node uses through $ref
└─ pages/<page>
   ├─ config      tree (nodes: type · props · children · actions · if · for)
   │              bindings (block event → chain) · routes · meta.routeState
   ├─ viewModel   the data {{ vm.* }} reads
   └─ locale      the texts {{ $locale.* }} reads
render   page/render → config + viewModel + locale → renderer
act      event → client actions (state, simapi.call, form.submit, …)
reply    form.submit → response actions (patch, vm.merge, navigate, …)
Select a node to read about its component here; search for an action, a context or a concept.
id: Identifier — Page id. Keep it equal to the containing folder name (not enforced); page/render returns it as pageId.
schemaVersion: string — Major.Minor. Author '2.0'. page/render echoes it; nothing checks or migrates it.
tree: TreeNode — The root node of the page — everything the page shows grows from it.
bindings?: PageBinding[] — Page-level rules: when a block emits an event, run an action chain. Each rule is `{ on, when?, do }`. A primitive wires its own events in its `actions`; a binding is how the page reacts to a block.
description?: string — A note about the page for its authors. It is stored but never sent to the page.
meta?: object — Settings for how the page is served and for tooling — not part of what it shows. `initViaCorezoid`, `vmKeys` and `routeState` change what `page/render` returns; `tags`, `author` and `deprecated` are for tooling only.
meta.author?: string — Who maintains the page. For tooling; not sent to the page.
meta.deprecated?: object — Marks the page as deprecated for tooling. Not sent to the page.
meta.deprecated.reason: string
meta.deprecated.replacedBy?: string
meta.initViaCorezoid?: boolean — `true` makes `page/render` call the form's Corezoid process (`/get`) to seed the view model. Without it the page starts from the `viewModel` file alone.
meta.routeState?: string[] — View-model keys the host mirrors into the URL so they survive reload/back-forward and can be shared as a link. Dot paths; the initial viewModel value is the default and is omitted from the URL. Only string/number/boolean values travel. Echoed by page/render as routeState.
meta.tags?: string[] — Free-form labels for tooling. Not sent to the page.
meta.vmKeys?: string[] — Optional allowlist of top-level view-model keys page/render keeps. Omitted = no filtering; a present array (including []) drops every other key, so [] ships an empty view model.
routes?: RouteDefinition[] — Short URLs that open this page: `/sf/{appKey}{path}`. Optional. Names must be unique and patterns must not overlap across the pages of a Smart Form; sim-api checks the whole table when a release is published and reports `route.*` codes.
title?: string — The page title, sent to the host by `page/render` when it is not empty.

## node — TreeNode, one node of the tree
One UI node: a component `type` with its `props`, `children` and event `actions`.
A node can also carry `if` / `visibility` conditions, a `for` loop, or be a `$ref` to a definition.
$ref?: string — Replaces this node with a reusable subtree from `definitions/<name>`. The server inlines it before the page renders.
actions?: {[key: string]: ClientAction[]} — Event name (`onClick`) → the action chain it runs. Only the events the component declares are wired. Inside the chain `$event` is what the component passed.
children?: TreeNode[] | {[key: string]: TreeNode[]} — Child nodes: a list, or named slots when the component declares them.
for?: object — Renders this node once per item of an array. `items` produces the array, `as` names the item (`$<as>`), `keyBy` picks the key field and `indexAs` names the position. Loop variables are visible in this node and its subtree only.
for.as: Identifier — The name of the current item: `as: "row"` makes it `$row` in this node and its subtree.
for.items: string — JSONata expression (bare or wrapped in {{ }}) returning an array; a non-array renders no copies.
for.indexAs?: Identifier — Optional name for the item's 0-based position (`indexAs: "i"` → `$i`).
for.keyBy?: string — The item field used as each copy's key. Without it the key is the item's `id`, and failing that its position.
id?: Identifier — The node's id: what `widget.call`, `$block.<id>` and bindings address. A plain identifier, never an expression. Inside a `for` the renderer renames each copy `<id>:<key>`, so a block in a loop cannot be targeted by a binding.
if?: string — Mounts the node only while this condition is truthy. JSONata, bare or in `{{ }}`. When falsy the node and its subtree are not mounted at all — use `visibility: "hidden"` to keep their state.
props?: {} — The component's props. Any value may be a `{{ }}` expression. Validated against the type's contract when the page is saved, not when it renders.
slot?: string — Which named slot of the parent this node goes into.
type?: string — The component this node renders — one of the catalog types. An unknown type renders the renderer's fallback and is refused by sim-api at save.
variant?: string — A variant name for the component, when its contract defines one.
visibility?: 'visible'|'hidden'|'disabled' | string — Shows, hides or disables the node: `visible`, `hidden`, `disabled`, or an expression resolving to one. Bare or in `{{ }}`, like `if`. The three literals stay literals; any other result is `visible`. `hidden` keeps the node mounted (its state survives the toggle); `if` unmounts it.
Identifier: string ^[A-Za-z_][A-Za-z0-9_-]*$ — ECMAScript-like identifier plus '-'. Reserved prefixes: '__', '$'.
A node with `for` renders once per item of an array, each copy seeing its item as `$<as>`.
`items` must produce an array — anything else renders no copies. Copies are keyed by `keyBy`, the item's `id` or its position, and a node inside is renamed `<id>:<key>`.

## expressions — {{ }} and what they can read
A JSONata expression in `{{ }}` that computes a prop value from the page's data when the page renders.
A string that is exactly one `{{ … }}` takes the expression's own type — a number stays a number. A string with text around it interpolates each part into text. `if`, `visibility`, `for.items` and a binding's `when` are expressions already, so there the braces are optional.
An expression cannot change anything: it has no side effects, and an error or a timeout yields an empty value instead of breaking the page.
Expression: string — Either a literal string, or a string containing one or more {{ JSONata }} expressions. Reactively re-evaluated on render.
$<as> — The current item inside a `for` directive, under the name its `as` gives (`as: "row"` → `$row`). `indexAs` adds the item's position under a second name.
$block — Another block on the page, by its node `id`: `$block.<id>.state.<key>` reads its public state. `$block.<id>.event.<name>` names one of its events — the form a binding's `on` uses. A block id may contain hyphens; the renderer quotes them for you.
$error — What failed, inside an `onError` chain — usually a sim-api error. Its fields: `message`, `code`, `kind` (`application`, `transport`, `timeout`, `aborted`), `method`, `reason`, `reasonParams`, `reqId`.
$event — The payload of the event being handled — inside an action chain, a binding's `when` and its `do`. For a primitive's action it is the first argument the component passes (`TextInput` / `Select` `onChange`: `{ value }`); in a binding, the bus event's payload; in `form.submit.onSuccess`, the submit reply `{ code, data, actions }`.
$form — Reserved — always `{}` today. Read a form's values from `vm.<valueKey>`.
$locale — The page dictionary for the active language: `$locale.<key>`.
$now — The current time as an ISO 8601 string, refreshed on every evaluation.
$params — The short-URL route parameters — the same object as `$route.params`, empty on a technical URL. `int` parameters are numbers; `slug` and `uuid` parameters are strings.
$query — The URL query of the page on screen, as strings: `$query.<key>`. The last value wins for a repeated key; `jwt` and `tmpsid` are removed. `{}` when there is none.
$result — This chain's results: `$result.<name>` for every earlier `simapi.call` / `widget.call` with `assignTo`. The last `form.submit` reply is there too, under `` $result.`$submit` ``. Results live only until the chain ends; to keep one, write it to the view model with a `state` action.
$route — How the page was opened: `{ kind: 'direct', params: {} }` for a technical URL, or `{ kind: 'dynamic', name, params }` for a short `/sf/…` URL.
$theme — The polarity of the theme the page shows: `light` or `dark`.
$themeId — The id of the active theme: `light`, `dark`, `darcula` or a theme the form defines.
$themes — The theme ids the viewer may switch to (`themes.switchable`) — the options of a `theme.set` picker.
$user — The signed-in user — `id`, `login`, `nick` and, when set, `photo`; absent for a guest. There are no roles or permissions here: gate the UI on data your process puts in the view model — the API enforces access, not the UI.
vm — The page's data: what `page/render` returned in `viewModel`, plus every later `state` write and backend patch. Read it as `vm.<path>` (`{{ vm.order.total }}`). A path that does not exist evaluates to nothing, so a bound prop falls back to its default rather than failing.

## bindings — PageBinding, the page's reactions to block events
A page-level rule: when a block emits an event, run an action chain.
`on` names the event (`$block.<id>.event.<name>`), the optional `when` filters it, and `do` is the chain. A primitive wires its events in its own `actions` instead; a binding is how a page reacts to a block it cannot otherwise reach into.
When a block emits an event, run an action chain.
do: ClientAction[] — The chain to run, with `$event` = the event's payload and a fresh `$result`. Every emission runs its own chain.
on: string — The event this rule listens to: `$block.<blockId>.event.<eventName>`, written without `{{ }}`. Both parts are identifiers, so a block inside a `for` (id `<id>:<key>`) cannot be targeted.
when?: string — Optional guard: the chain runs only when it is truthy. Bare or in `{{ }}`. It sees `vm`, `$event` (the payload) and the host variables — not `$block` state and no loop variables.

## actions — ClientAction, the steps of an action chain
The list of client actions an event runs, in order, each one waiting for the one before.
A step that fails stops the rest of the chain — unless it is a `simapi.call` or `form.submit` with its own `onError` branch, which runs instead. A step whose arguments do not match its schema is skipped, and the chain goes on.
One step of an action chain — a closed set of 17 action types, keyed on `type`.

### widget.call — Call a block
Calls one of a block's `api` methods; its return value goes to `$result.<assignTo>`.
method: string — One of the block's `api` methods (see the block's reference).
target: Identifier — The node id of a block on this page.
args?: any — Passed to the method as is; not checked against its declared args.
assignTo?: Identifier — Puts the method's return value in `$result.<name>` for the rest of this chain.
timeoutMs?: integer — How long to wait for a method that returns a promise (default 10000); running out stops the chain. An unknown target or method throws in development and does nothing in production.

### simapi.call — Call sim-api
Calls a sim-api method; the reply goes to `$result.<assignTo>` for the rest of the chain.
sim-api checks the viewer's access. The reply is never applied as response actions, and there is no `onSuccess` — success is simply the next action.
method: string — The sim-api JSON-RPC method (`actor/list`). `page/submit` gets the page's coordinates from the runtime.
assignTo?: Identifier — Puts the reply in `$result.<name>` for the rest of this chain — not in the view model. To keep it, follow with a `state` action: `"value": "{{ $result.regions }}"`.
onError?: ClientAction[] — Runs with `$error` when the call fails; then the outer chain continues. Without it, a failure stops the chain.
params?: any — The method's params.

### state — Write to the view model
Writes a value into the view model, or merges an object into it.
`mode: "set"` writes `value` at `path`; `mode: "merge"` shallow-merges `patch` into the object at `path`.
mode: 'set'|'merge' — `set` writes one value; `merge` shallow-merges an object.
path: string — Where to write: dots or brackets (`rows[0].name`), or a JSON Pointer (`/rows/0/name`). A leading `vm.` is allowed. `""`, `"/"` and `"vm"` mean the whole view model.
patch?: {} — The object to merge (`merge` only, and required there). Shallow: one level deep. A missing or non-object target counts as `{}`.
value?: any — The value to write (`set` only, and required there). Missing parents are created — an array when the next segment is a number. At the root it replaces the whole view model.

### overlay.open — Open a modal or drawer
Opens an overlay and renders its `content` above the page.
The content shares the page's view model and bus but sees no loop variables — copy the row into `vm` first. For a dialog, make the content a `Modal` whose `onClose` runs `overlay.close`.
id: Identifier — Names the overlay; opening the same key again replaces it.
surface: 'modal'|'drawer' — Part of the overlay's key (`surface` + `id`); it adds no chrome.
content?: TreeNode — The node to render in the overlay. Without it nothing renders.
propsOverride?: {} — Accepted and currently unused.

### overlay.close — Close a modal or drawer
Closes the overlay with this `surface` and `id`.
id: Identifier — The id the overlay was opened with.
surface: 'modal'|'drawer' — The surface the overlay was opened on.
intent?: 'discard'|'confirm' — Accepted and currently unused — nothing reads it.

### navigate.local — Go to a page
Opens another page of this Smart Form, an in-app path or an external URL.
A literal `to: ""` stays on the page and changes only the query. A value that resolves to nothing is skipped.
The `#b=` fragment is not carried over. On a production page, a bare page id whose page has exactly one route without parameters goes to that short URL.
to: string — A page id of this Smart Form, an in-app path starting with `/`, or an external `http(s)://` or `//` URL. A literal `""` stays on the current page and changes only the query. A value that resolves to nothing — an expression that resolves to `""` included — is skipped (`renderer.navigate.noTarget`).
history?: 'push'|'replace' — `push` adds a history entry (default); `replace` replaces the current one.
prefetch?: boolean — `false` stops the host from preloading the target page on hover or focus. Default `true`. Set it when the target's `/get` is not a cheap read.
query?: {[key: string]: string} — Replaces the URL query (no merge with the current one). Each value is an expression. Objects are JSON-encoded, other values turned into text, empty ones dropped.
target?: '_self'|'_blank' — `_blank` opens a new tab; default `_self`.

### navigate.route — Go to a route
Opens a route the Smart Form declares in its pages' `routes`, by name.
The host builds the short URL `/sf/{appKey}{path}` from the active release's route table. A refusal — an unknown name, a value that does not fit its parameter, a develop page with no route table — stops the chain.
name: string — A route name from the Smart Form's routes (`graph.layer`).
blockRoutes?: {[key: string]: string} — Block id → block-local state for the new page's `#b=` fragment. Each value is an expression.
history?: 'push'|'replace' — `push` adds a history entry (default); `replace` replaces the current one.
params?: {[key: string]: string} — One expression per `:param` of the route; each must resolve to a string or a number. `null`, a boolean, an object or an array throws `route.invalidParamValue`.
query?: {[key: string]: string} — The URL query, as on `navigate.local`. Each value is an expression.
target?: '_self'|'_blank' — `_blank` opens a new tab; default `_self`.

### form.validate — Validate a form
Checks a form's fields and writes its errors and validity to the view model.
It does not stop the chain when the form is invalid — gate the next step with `{ "type": "if", "cond": "vm.valid.<valueKey>", "then": [ … ] }`. An unknown form id counts as valid and writes nothing.
form: Identifier — The `Form` node's id.
scope?: Identifier[] — Check only these field names. Default: every field the form declares, on screen or not.
setErrors?: boolean — Write the results (default `true`): `vm.errors.<valueKey>` and `vm.valid.<valueKey>`. With `false` nothing observable happens.

### form.submit — Submit a form
Sends a form's values to the Corezoid process or a sim-api method, then runs `onSuccess` or `onError`.
It does not validate — run `form.validate` and an `if` first. There is no double-submit guard, and the page's URL query is not sent. Response actions in the reply are applied before `onSuccess`.
formId: Identifier — The `Form` node's id. Its `vm.<valueKey>` is sent as `formData`. Keys not declared in the form's `fields` are sent too; an unknown form sends `{}`.
via: 'corezoid'|'simapi' — `corezoid`: `page/submit` → the form's process `/send`. `simapi`: calls `simapiMethod` with `{ formData, …simapiExtraParams }`.
onError?: ClientAction[] — Runs with `$error` when the call itself fails (network, access, Corezoid unreachable). Without it, a failure stops the chain.
onSuccess?: ClientAction[] — Runs after the reply, with `$event` = the reply. A Corezoid reply with a non-2xx `code` still lands here — branch on `$event.code`.
simapiExtraParams?: {} — Extra params, spread next to `formData`.
simapiMethod?: string — The sim-api method to call; required with `via: "simapi"`.

### form.reset — Reset a form
Restores a form to its baseline and clears its errors.
The baseline is the values it had when it mounted, or at its last successful `form.submit`. An unknown id does nothing.
formId: Identifier — The `Form` node's id.

### notify — Show a toast
Shows a toast message.
level: 'info'|'warn'|'error'|'success' — The toast's style: `info`, `warn`, `error` or `success` — `warn`, not `warning`.
title: string — The message. An expression; if it resolves to nothing, the template text is shown.
expireMs?: integer — Milliseconds before the toast closes; `0` keeps it until closed. Defaults by level: success 3000, info 5000, warn 7000, error 0.
helperText?: string — A second line under the title.
toastId?: string — A test id for the toast. A second toast with the same id does not replace the first.

### bus.publish — Publish an event
Publishes an event on the page's bus, which bindings listening to it receive at once.
name: string — The event's name; a binding can match only identifier names.
sourceId: Identifier — The id the event is published under; it need not be a mounted block. A binding listens to it as `$block.<sourceId>.event.<name>`.
payload?: any — What listeners receive as `$event`. It is delivered at once, to the bindings listening now.

### copy — Copy to clipboard
Copies text to the clipboard, optionally with a toast.
A failed write stops the chain.
value: string — The text to copy — an expression; whatever it resolves to is copied as text.
notify?: object — A toast after copying: `{ level: "info" | "success", title }`. The title is not an expression.
notify.level: 'info'|'success'
notify.title: string

### theme.set — Switch theme
Switches the page to another of the form's themes.
Applied only if the form lists the theme in `themes.switchable`; the runtime remembers the viewer's choice for this form.
theme: string — A theme id, or an expression resolving to one (`{{ $event.value }}`). Ignored unless it resolves to a non-empty string.

### log — Write to the log
Writes a telemetry event (`renderer.action.log`) — for debugging a chain.
The runtime's console shows only `warn` and `error`.
level: 'debug'|'info'|'warn'|'error' — How severe the entry is: `debug`, `info`, `warn` or `error`.
message: string — The message, logged as written.
fields?: {} — Extra data, logged as written.

### delay — Wait
Waits, then the chain continues.
Not a debounce: every event still runs its own delayed chain.
ms: integer — How long to wait, in milliseconds (0–5000).

### if — Branch
Runs `then` when the condition is truthy, otherwise `else`.
Both branches share the outer chain's `$result`; a failure inside one stops only that branch.
cond: string — The condition, bare or in `{{ }}`. An expression error counts as falsy.
then: ClientAction[] — The chain to run when the condition is truthy.
else?: ClientAction[] — The chain to run otherwise.

## responses — ResponseAction, what a form.submit reply may ask the page to do
What a `form.submit` reply may ask the page to do: one of six actions, applied in order, exactly as sent.
They come from the Corezoid process's `/send` reply (`{ "code": 200, "data": { "actions": [ … ] } }`) or from the result of a `via: "simapi"` method. A `simapi.call` reply is never applied as actions, and realtime frames carry none. Then `form.submit.onSuccess` runs. Put a `navigate` last: view-model writes after it land on the page being left.
What a `form.submit` reply may ask the page to do — a closed set of six types, applied in order.
They come from the Corezoid process's `/send` reply (`data.actions`) or a `via: "simapi"` method's result, and are applied exactly as sent: no expressions. Realtime frames never carry them.

### navigate — Go to a page
Opens a page, an in-app path or an external URL — the same routing as `navigate.local`.
to: string — A page id of this Smart Form, an in-app path starting with `/`, or an external URL.
history?: 'push'|'replace' — `push` adds a history entry (default); `replace` replaces the current one.
query?: {[key: string]: string} — The URL query; every value must be a string.
target?: '_self'|'_blank' — `_blank` opens a new tab; default `_self`.

### patch — Patch the tree or view model
Applies a JSON Patch to the rendered tree or to the view model — atomically.
If any op fails, none is applied (telemetry `renderer.patch.rollback`) and the next action still runs.
ops: JsonPatchOp[] — The JSON Patch operations, at least one. Paths are JSON Pointers (`/rows/0/name`). For `tree` they start at the root node (`/props/title`, `/children/0/props/text`), for `vm` at the view model.
target?: 'tree'|'vm' — What to patch: `tree` (default) or `vm`.

### notify — Show a toast
Shows a toast, like the client `notify` — but every value, title and helper text included, is shown as sent.
level: 'info'|'warn'|'error'|'success' — The toast's style: `info`, `warn`, `error` or `success` — `warn`, not `warning`.
title: string — The message. An expression; if it resolves to nothing, the template text is shown.
expireMs?: integer — Milliseconds before the toast closes; `0` keeps it until closed. Defaults by level: success 3000, info 5000, warn 7000, error 0.
helperText?: string — A second line under the title.
toastId?: string — A test id for the toast. A second toast with the same id does not replace the first.

### vm.merge — Merge into the view model
Deep-merges an object into the view model.
Nested objects merge key by key; arrays, scalars and `null` replace; no key is ever removed.
patch: {} — The object to merge into the view model.

### assign — Set a view-model value
Sets one value in the view model.
Same paths as `state`; missing parents are created; `""`, `"/"` or `"vm"` replaces the whole view model.
path: string — Where to write: `status`, `vm.status` and `/status` are the same.
value: any — The value to write, as sent.

### redirect — Leave the app
Leaves the app for an absolute `http(s)` URL.
url: string — The URL; it must start with `http://` or `https://`.
history?: 'push'|'replace' — Accepted; the runtime always opens the URL as a new navigation (`location.assign`).

View-model keys the host mirrors into the URL, so a reload, back/forward or a shared link restores them.
Declare them in `meta.routeState`; a page reads them as ordinary `vm` keys.

## definitions — reusable subtrees, files definitions/<name>
A reusable subtree stored in `definitions/<name>`, used by a node with `$ref: "#/definitions/<name>"`.
The server inlines it before the page renders, so a definition costs nothing at runtime.
Reusable subtree referenced by $ref. Stored at <app-root>/definitions/<name>.
$ref: string ^#/definitions/[A-Za-z0-9_-]+$ — Replaces this node with a reusable subtree from `definitions/<name>`. The server inlines it before the page renders.
Contract: id is required for any node that participates in registry/bus (i.e. type set).
Contract: $ref is mutually exclusive with type/props/children/actions.
Rules (checked on a stand: save, page/render, release):
- A definition is a file definitions/<name> (application/json) in the app-root definitions folder, holding one node {id, type, props?, children?, actions?}. It is not checked when it is saved, only inside each page that uses it, when the page is rendered or released.
- An instance is {"id": "<own id>", "$ref": "#/definitions/<name>"} plus, if needed, if, visibility, for, slot or variant. A page saving an instance with type, props, children or actions is refused, and so is a nested name (#/definitions/cards/user): every definition sits directly in definitions/.
- The definition replaces the instance, then the instance's own keys replace the definition's same top-level keys (id, if, visibility, for, …). Props cannot differ per instance: vary content through data, e.g. a for on the instance repeats the definition per item, which reads the item as $<as> ({{ $f.label }}), or expressions over vm.
- Give every instance its own id. Ids are not checked for uniqueness: two instances without id both render with the definition root's id, so widget.call, bindings and $block cannot tell them apart. A definition root without id needs an id on every instance, else render and release are refused (missing property 'id'). Ids inside a definition repeat in every instance.
- A missing definition or a cycle saves, but render and release are refused: unresolved definition at /tree/… (missing, invalid, or cyclic). Wrong props inside a definition are refused the same way, at the resolved node.
- Instances in overlay.open content and in bindings are resolved too. Changing the definition file (smart_form_page_patch path definitions/<name>) changes every instance at the next render and release.

## data — the viewModel and locale files
ViewModel — Initial mutable data store. Shape is page-specific.
Locale — i18n dictionary. BCP 47 language tag → flat key → string.

## concepts

### form — Form
A `Form` node keeps its fields' values in `vm.<valueKey>`; `form.*` actions validate, submit and reset it.
`form.validate` writes `vm.errors.<valueKey>` and `vm.valid.<valueKey>`; `form.submit` sends a copy of `vm.<valueKey>` and does not validate on its own.

### overlay — Overlay
A modal or drawer opened by `overlay.open`, keyed by `surface` + `id`, rendered above the page.
Its `content` shares the page's view model and bus but sees no loop variables, so a row action copies the row into `vm` before it opens the overlay.
